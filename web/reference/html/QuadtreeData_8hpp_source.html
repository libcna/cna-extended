5// Ported from MonoGame.Extended's Collisions/QuadTree/QuadTreeData.cs (upstream file name has a
6// capital "T" in "QuadTreeData.cs"; the C# *class* itself is `QuadtreeData` with a lowercase "t" --
7// preserved exactly as-is, not "fixed" to match the file name).
8//
9// Ownership model (a real design decision upstream's GC made invisible, decided explicitly here):
10// a QuadtreeData is created and owned by QuadTreeSpace (see QuadTreeSpace.hpp) for the lifetime of
11// an inserted actor. QuadTree nodes that store a QuadtreeData in their Contents set, and the
12// QuadtreeData's own record of which QuadTree nodes currently reference it (`parents_`), both hold
13// only non-owning raw pointers into that externally-owned instance -- mirroring upstream, where a
14// QuadtreeData is a single GC-tracked object referenced from multiple places, never copied.
15// HashSet<QuadTree> `_parents` -> sharp-runtime's System::Collections::Generic::HashSet<QuadTree*>:
16// upstream never overrides Equals/GetHashCode on QuadTree, so C#'s default reference-equality
17// HashSet<T> semantics are exactly what a HashSet of raw pointers gives for free in C++ (no custom
18// std::hash specialization needed, unlike ActorPairKey in an earlier task, which genuinely needed
19// value equality).
