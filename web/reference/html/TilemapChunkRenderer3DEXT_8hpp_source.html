4// CNA::Extended::World3DEXT::TilemapChunkRenderer3DEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design (Phase 12 E, 2026-07-15,
6// user-requested "extend later" item).
7//
8// An OPT-IN alternative to TilemapRenderer3DEXT's per-tile draw calls, not a replacement --
9// matches this project's established "keep the simple version, add an alternative for when
10// you need it" pattern (e.g. Octree3DEXT alongside SpatialHash3DEXT, Phase 11 B).
11// TilemapRenderer3DEXT.hpp's own header comment already documented this exact future path:
12// "per-chunk batching (merging many tiles' geometry into one draw call, the way
13// TilemapRenderer.cpp's own 2D layer batching does) remains a documented future
14// optimization."
15//
16// RebuildEXT groups every visible tile FACE (naive neighbor-based culling: a face is only
17// emitted if the neighboring cell along that face's normal is empty -- Tilemap3DEXT::
18// HasTileEXT) into one combined VertexBuffer/IndexBuffer per (chunk coordinate, texture)
19// pair -- sub-grouping by texture within each chunk mirrors 2D TilemapRenderer.cpp's own
20// per-texture TileBatch precedent, since one draw call can only bind one texture and
21// different tile IDs can resolve to different textures (TilemapTileset3DEXT::
22// GetTileTextureEXT). Reuses CubeMeshRenderSystemEXT::BuildUnitCubeMeshEXT's exact per-face
23// corner/normal/UV layout, just baking each face's vertices directly into world space
24// (position = tile world center + local corner * tileSize) instead of drawing a shared unit
25// mesh once per tile with a per-draw world matrix.
26//
27// RebuildEXT is a full rebuild, not incremental -- call it again whenever the tilemap
28// changes. This matches SpatialHash3DEXT::Reset()/Octree3DEXT::Reset()/QuadTreeSpace::
29// Reset()'s own established "full rebuild, not incremental" precedent (see those files'
30// header comments for the same reasoning: simplicity over an incremental-update fast path
31// with no demonstrated need yet).
32//
33// Frustum culling happens per (chunk, texture) BATCH (one BoundingBox built from its own
34// baked vertices via BoundingBox::CreateFromPoints), not per tile -- coarser than
35// TilemapRenderer3DEXT's per-tile culling, but that coarseness is the whole point: far
36// fewer, larger draw calls is the batching win this phase exists for.
37//
38// ChunkBatchEXT is a private, forward-declared nested struct (full definition in the .cpp
39// only) since the number of chunk batches is only known at RebuildEXT time -- an incomplete
40// type inside std::vector<std::unique_ptr<T>> requires the owning class's destructor to be
41// defined where T is complete (see ParticleEmitter3DEXT's Phase 11 C-1 precedent for the
42// identical requirement; unlike that class, this one has no move operations to define
43// alongside it -- see the constructor declarations below for why).
