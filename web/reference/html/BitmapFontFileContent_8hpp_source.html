5// Ported from MonoGame.Extended's Content/BitmapFonts/BitmapFontFileContent.cs. Upstream's block
6// structs use `[StructLayout(LayoutKind.Explicit)]`/`[FieldOffset(n)]` so `Marshal.PtrToStructure`
7// can reinterpret a raw byte buffer directly onto the struct -- a .NET-marshaling-specific
8// mechanism with no safe, portable C++ equivalent (relying on C++ struct layout/padding to match
9// exact byte offsets across compilers would be fragile, not faithful). These block types are kept
10// as plain structs with the same named fields in the same order; `BitmapFontFileReader.cpp`
11// reproduces the exact same field values by reading each field individually at its point of use
12// (via `BinaryReader` for the binary format, node attributes for XML, tokens for text) rather than
13// one raw reinterpret -- same end result (identical field values), different, portable mechanism.
14// Upstream's plain public fields (not C# properties) are kept as plain public fields here too,
15// matching this project's established `Size`/`RectangleF`-style convention for such types.
