5// Ported from MonoGame.Extended's Collisions/QuadTree/QuadTree.cs: a hierarchical quadtree for
6// broadphase overlap queries.
7//
8// Ownership model: upstream's `List<QuadTree> Children` are GC-owned by the parent node; ported as
9// `std::vector<std::unique_ptr<QuadTree>>` (Children genuinely owns its child nodes -- nothing else
10// references them). `HashSet<QuadtreeData> Contents` is ported as
11// `System::Collections::Generic::HashSet<QuadtreeData*>` -- non-owning, since a QuadtreeData is
12// owned by the QuadTreeSpace that created it (see QuadtreeData.hpp/QuadTreeSpace.hpp), not by the
13// tree nodes that merely reference it. As with QuadtreeData's own `_parents` set, upstream never
14// overrides Equals/GetHashCode on QuadtreeData, so C#'s default reference-equality HashSet<T>
15// semantics are exactly what a HashSet of raw pointers gives for free in C++.
16//
17// `protected` visibility on Children/Contents/CurrentDepth/MaxDepth/MaxObjectsPerNode is preserved
18// exactly, even though no subclass exists in this codebase yet, matching this project's "port 1:1"
19// mandate.
20//
21// `Queue<QuadTree>` (BFS traversal in NumTargets/Shake) -> sharp-runtime's
22// System::Collections::Generic::Queue<T>, matching this project's "reuse sharp-runtime types" rule.
23//
24// `ArgumentNullException.ThrowIfNull` on Insert(QuadtreeData)/Remove(QuadtreeData) has no C++
25// equivalent to preserve -- both take QuadtreeData& (a reference, not representable as null),
26// matching this project's established convention (see ActorPairKey.hpp's header comment) of
27// dropping such checks where the parameter type itself rules out null.
28//
29// Remove(QuadtreeData)'s `throw new InvalidOperationException(...)` on a non-leaf node ->
30// std::logic_error, matching ObjectPool<T>::New's precedent for InvalidOperationException-style
31// C# exceptions with no closer std:: equivalent.
