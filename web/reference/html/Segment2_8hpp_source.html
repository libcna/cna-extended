10// *** LIKELY UPSTREAM BUG, PRESERVED FOR FIDELITY -- flagged prominently, not silently fixed ***
11// SquaredDistanceTo(Vector2) has a branch that computes `endToPoint.Dot(endToPoint)` (the correct
12// answer for "point projects beyond the End of the segment") but never returns it -- the result
13// is discarded and execution falls through to the "point projects onto the segment interior"
14// formula regardless. This looks like a missing `return` typo (the two other branches both
15// return immediately; a code comment even says "Handle cases where point projects outside
16// segment", implying both boundary cases were meant to return early). The C++ port below
17// reproduces this exact behavior byte-for-semantics -- per this project's explicit "port 1:1,
18// no simplification" requirement, "fixing" an upstream bug during a mechanical port is not this
19// port's call to make. See Segment2.cpp's SquaredDistanceTo for where this is replicated, and
20// the ported test file for a case demonstrating the resulting wrong answer for a point beyond
21// End. Recommend the user decide whether to file this upstream or diverge from it locally.
22//
23// All members are now ported. The two Intersects(RectangleF|BoundingRectangle, out Vector2)
24// overloads call PrimitivesHelper.IntersectsSlab, landed once PrimitivesHelper was ported
25// (task 22 -- verified genuinely unblocked, not assumed).
26//
27// IEquatable<Segment2>/IEquatableByRef<Segment2> are not implemented as C++ interfaces (matches
28// the precedent set by the bounding-volume types) -- just a plain Equals(const Segment2&).
