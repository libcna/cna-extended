5// Ported from MonoGame.Extended's Tilemaps/Tiled/Document/*.cs (~24 files). Grouped into one
6// header for the same reason TilemapData.hpp groups ~25 related DTOs into one file: these are
7// pure, behavior-free parse targets, all sharing the `MonoGame.Extended.Tilemaps.Tiled.Document`
8// namespace.
9//
10// DESIGN DEVIATION, matching TilemapData.hpp's own precedent: plain public mutable fields
11// instead of getXProperty()/setXProperty() -- these are C# auto-implemented properties with no
12// logic, semantically indistinguishable from plain fields.
13//
14// REFLECTION GAP: upstream deserializes this whole tree via `System.Xml.Serialization.XmlSerializer`
15// driven by [XmlAttribute]/[XmlElement]/[XmlText] attributes on every property -- a genuine
16// reflection dependency with no C++ equivalent. TiledTmxParser.cpp works around this not by
17// dropping the two-stage (raw XML -> Document model -> TilemapData) architecture, but by hand-
18// writing the XML-to-Document-model walk that XmlSerializer would otherwise generate via
19// reflection, using the already-ported System::Xml DOM (XmlDocument/XmlElement) directly. The
20// Document model types themselves are unaffected by this -- they're still exactly what
21// TiledTilemapDataConverter.cpp consumes, faithfully matching upstream's architecture.
22//
23// [XmlIgnore] `Texture2D Texture` fields (runtime-loaded, not part of XML parsing) are ported as
24// non-owning `Texture2D*` (external-GPU-resource convention, matching Tilemap::ownedTextures_'s
25// established pattern) -- though in practice TilemapFactory/TiledTilemapDataConverter's own
26// texture-loading path (via TexturePath strings resolved by TilemapFactory) is what's actually
27// used; these fields are carried for structural fidelity, not currently populated by the parser.
28//
29// TiledTilesetRefXml : TiledTilesetXml and the Tiled{Tile,Object,Image,Group}LayerXml : TiledLayerXml
30// inheritance hierarchies are preserved (upstream's own polymorphic XmlElement-attribute-driven
31// deserialization relies on exactly this hierarchy for its `List<TiledLayerXml>` covariant
32// storage), with virtual destructors added for safe dynamic_cast dispatch in
33// TiledTilemapDataConverter's format-detection switches (C# `is`/pattern-matching's C++
34// equivalent).
