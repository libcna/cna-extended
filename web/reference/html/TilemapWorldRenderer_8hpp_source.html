5// Ported from MonoGame.Extended's Tilemaps/Rendering/TilemapWorldRenderer.cs.
6//
7// *** ARCHITECTURAL DEVIATION: DefaultEffect -> BasicEffect (not a literal port) ***
8// See TilemapRenderer.hpp's top comment for the full rationale (genuine XNA `BasicEffect` vs.
9// MonoGame.Extended's own `DefaultEffect`, CNA's `Effect` base having no generic
10// `Parameters`/`CurrentTechnique.Passes` reflection surface, and the idiomatic
11// SetVertexBuffer/SetIndexBuffer/Apply()/DrawIndexedPrimitives flow this port uses instead) -- it
12// applies identically here. The public `Effect Effect { get; set; }` property is likewise narrowed
13// to `BasicEffect&` for the same reason.
14//
15// `Dictionary<WorldGroupKey, WorldGroup>`-shaped grouping does not exist in this class the way it
16// does in `TilemapWorldSpriteBatchRenderer.cs` -- upstream `TilemapWorldRenderer.cs` groups
17// directly into a local `Dictionary<TileBatchKey, TileAccumulator>` inside `Load`, where
18// `TileBatchKey` is a `readonly record struct(int WorldDepth, Texture2D Texture, Vector2
19// ParallaxFactor)`. Matching `TilemapWorldSpriteBatchRenderer.hpp`'s own documented precedent for
20// its structurally identical `WorldGroupKey`/`WorldRoomKey` local grouping problem: a
21// `Vector2`-containing key has no `std::hash` specialization in this project, and load-time group
22// counts are small (bounded by distinct (depth, texture, parallax) combinations, not tile count),
23// so this port uses a linear scan over a `std::vector<TileAccumulator>` instead of a hash map --
24// entirely local to `Load()`'s .cpp implementation, never exposed here.
25//
26// `List<WorldBatch> _worldBatches` -> `std::vector<WorldBatch> worldBatches_`, a private nested
27// struct kept COMPLETE in this header (or the mapped_type of this class's own member field is
28// under-defined) -- unlike `TilemapWorldSpriteBatchRenderer.hpp`'s forward-declared `WorldGroup`
29// (whose owning container is `std::vector<std::unique_ptr<WorldGroup>>`, needing only the pointee
30// forward-declared), `worldBatches_` here holds `WorldBatch` directly by value, so it must be
31// complete wherever this class definition is parsed.
32//
33// `IEnumerable<Tilemap> tilemaps` -> `const std::vector<Tilemap*>&` (non-owning: this renderer
34// never owns the tilemaps it bakes), matching `TilemapWorldSpriteBatchRenderer::Load`'s identical
35// translation of the same upstream parameter shape.
