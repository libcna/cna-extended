4// CNA::Extended::World3DEXT::DebugDrawComponentEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design.
6//
7// A per-entity list of world-space debug line segments, drawn every frame by
8// DebugDrawSystemEXT. Adapted from cna-scene::DebugDraw's "lines/boxes for development
9// visualization" concept (read as reference material only; see CubeMeshComponentEXT.hpp's
10// header comment for why no NOTICE.md entry is needed for cna-scene-informed design) --
11// re-implemented as an ECS component (a per-entity line list) rather than cna-scene's own
12// immediate-mode global draw-list API, so an entity can carry its own persistent debug
13// visualization (e.g. always drawing its own collision bounds) instead of every call site
14// re-submitting lines each frame.
15//
16// AddDebugBoxLinesEXT/AddDebugFrustumLinesEXT cover the two cases plan3d.md's Phase 6
17// bullet explicitly calls for ("drawing Collisions3DEXT bounds and Camera3DEXT frustums
18// for debugging") -- BoundingBox::GetCorners()/BoundingFrustum::GetCorners() share the
19// same real CNA 8-corner ordering (near/front face 0-3, far/back face 4-7), so one shared
20// wireframe-from-corners helper covers both.
21//
22// AddDebugSphereLinesEXT (Phase 12 A, 2026-07-15, user-requested "extend later" item) adds
23// sphere wireframes -- deferred in the first pass since CollisionShape3DEXT already exposes
24// a BoundingBox for any shape via getBoundingBoxProperty(), so box wireframes alone covered
25// every collision shape kind at the time; added now on request. No sphere-wireframe helper
26// exists anywhere in cna/easy-3d to reuse, so this draws 3 orthogonal great circles (XY/XZ/YZ
27// planes through Center, each approximated by segmentsPerCircle line segments) -- the
28// standard sphere-wireframe approximation, not a full lat/long grid (which would need far
29// more line segments for a debug-only visualization with no real added clarity).
