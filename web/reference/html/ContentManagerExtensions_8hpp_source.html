5// Ported from MonoGame.Extended's Content/ContentManagerExtensions.cs. Extension methods -> free
6// functions, matching this project's established convention (see Content/ExternalResourceResolvers.hpp).
7// Not xnb-specific: the `Load<T>(ContentManager&, path, loader)` overloads are a generic
8// pluggable-loader mechanism used by this project's own JsonContentLoader/TextContentLoader,
9// unrelated to the excluded Content Pipeline's `.xnb` readers.
10//
11// Upstream has two loader interfaces: `IContentLoader<out T>` (T fixed per implementation, e.g.
12// `TextContentLoader : IContentLoader<string>`) and a non-generic `IContentLoader` whose single
13// method (`T Load<T>(...)`) is itself generic -- a "non-generic interface with a generic method"
14// has no direct C++ equivalent (virtual functions cannot be templates). `IContentLoader<T>` ports
15// directly as a normal interface template. For the non-generic `IContentLoader`, every real call
16// site in this codebase (`JsonContentLoader`, used by `TextureAtlasJsonConverter`) always uses a
17// concrete loader type known at the call site, never through a polymorphic `IContentLoader*` -- so
18// the `Load<T>(ContentManager&, path, IContentLoader&)` overload below is a template that
19// duck-types its loader parameter (any type exposing `template<typename T> T Load(ContentManager&,
20// const std::string&)`) rather than requiring a common virtual base, matching how it's actually
21// used everywhere upstream while staying valid C++.
