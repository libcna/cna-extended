4// CNA::Extended::World3DEXT::Modifier3DEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design.
6//
7// 3D counterpart of CNA::Extended::Particles::Modifiers::Modifier, brought to parity
8// (2026-07-14, user-requested), with one deliberate behavioral deviation from the 2D 1:1
9// mirror, found and resolved during implementation (not assumed):
10//
11// 2D's Modifier::InternalUpdate paces a full pass over the particle buffer across several
12// frames according to Frequency, but -- critically -- the per-particle Update() call it
13// dispatches to always receives `cycleTime_` (1/Frequency) as its elapsed-time argument, NOT
14// the real elapsed time of the InternalUpdate() call that triggered it. That is a real,
15// intentional 2D design choice (every particle receives a full cycle's worth of simulated
16// time exactly once per cycle, spread across frames for performance), but it means a single
17// large-elapsedSeconds call (e.g. a test calling UpdateEXT(0.5f, ...) as a convenience
18// shortcut for "half a second passed", rather than many real small per-frame calls) would
19// apply only `cycleTime_` (~0.0167s at the default 60Hz) of simulated change, not the full
20// 0.5s -- a real, observable simulation-timing difference from ParticleEmitter3DEXT's
21// existing (pre-this-architecture) behavior, where every active particle receives the exact
22// real deltaSeconds of each UpdateEXT call, unconditionally, every call.
23//
24// This port's InternalUpdate keeps Frequency's *particle-count* pacing (how many of the
25// total particles are touched this call) but passes the real elapsedSeconds through to
26// Update() instead of `cycleTime_` -- whichever particles a given call does touch receive
27// physically correct time deltas, rather than a stale fixed-size one. ParticleEmitter3DEXT's
28// own built-in default modifiers (AgeModifier3DEXT, LinearGravityModifier3DEXT) additionally
29// override Frequency to an effectively-unthrottled value specifically so the emitter's
30// pre-existing "every particle, every call" behavior is preserved exactly (verified against
31// the full pre-existing ParticleEmitter3DEXTTests.cpp/ParticleRenderSystem3DEXTTests.cpp
32// suite, which needed zero behavioral changes for this reason) -- Frequency-based
33// count-throttling remains available and correctly implemented for any other modifier that
34// deliberately wants it for performance on very large particle counts.
