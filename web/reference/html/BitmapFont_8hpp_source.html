5// Ported from MonoGame.Extended's BitmapFonts/BitmapFont.cs. `_characters` (a
6// `Dictionary<int, BitmapFontCharacter>` of reference-type values in C#) becomes a
7// `Dictionary<int, std::shared_ptr<BitmapFontCharacter>>` -- cheap-to-copy, nullable-lookup-result
8// semantics matching upstream's reference-type dictionary values exactly.
9//
10// Upstream's `StringGlyphEnumerable`/`StringGlyphEnumerator` (and the StringBuilder-keyed
11// equivalents) are C#'s struct-based custom `IEnumerable<T>`/`IEnumerator<T>` pattern; ported
12// as real C++ input iterators exposing `begin()`/`end()` so `for (auto glyph : font.GetGlyphs(...))`
13// works with range-for, preserving the same lazy, allocation-free, one-glyph-at-a-time evaluation
14// as upstream (not materialized into a container up front).
15//
16// `FromFile`/`FromStream` load real page-texture images from disk via CNA's `GraphicsDevice`, and
17// each loaded `BitmapFontCharacter::TextureRegion` (`Texture2DRegion`, holding a non-owning
18// `Texture2D*`) needs those page textures to outlive the font. `BitmapFont` therefore owns them in
19// `pageTextures_` (`std::vector<std::unique_ptr<Texture2D>>` for pointer stability across growth) --
20// in upstream this is implicit: the page `Texture2D`s are GC-rooted transitively through the
21// `Texture2DRegion`s stored inside the font's own `_characters` dictionary, so the font is already
22// the real, if implicit, root keeping them alive. This makes that same relationship an explicit
23// C++ ownership member instead.
