5// Ported from MonoGame.Extended's Serialization/Json/TextureAtlasJsonConverter.cs. Stateful (needs
6// a ContentManager& and a path), so ported as an explicit class per
7// TextureRegion2DJsonConverter.hpp's header-comment rationale, not an
8// nlohmann::adl_serializer<T> specialization.
9//
10// Fidelity note: upstream's `Read` has two branches. The JSON-string branch (a bare asset-name
11// reference) is genuinely broken in upstream itself -- its own source carries the comment
12// "TODO: (Aristurtle 05/20/2024) What is this for? It's just an if block that throws an
13// exception. Need to investigate." followed by dead setup code and an unconditional
14// `throw new NotImplementedException()`. Preserved as-is (throws, does not attempt to make it
15// work) per this project's port-faithfully mandate -- this is a real upstream bug, not something
16// to silently "fix" or skip. The JSON-object branch (an inline `{texture, regionWidth,
17// regionHeight}` atlas definition) is complete and functional upstream and is ported faithfully.
18//
19// Ownership note (a genuine C#-GC-vs-C++ divergence, not present in the upstream source): the
20// returned `Texture2DAtlas` holds a non-owning `Texture2D*` into the texture it loads (matching
21// this project's established `Texture2DAtlas` ownership convention). Upstream relies on
22// `ContentManager` itself keeping the loaded `Texture2D` reference alive for as long as needed;
23// this port's `ContentManager::Load<T>()` returns `Texture2D` by value, so nothing outside this
24// converter would otherwise keep it alive. `TextureAtlasJsonConverter` therefore owns every
25// texture it loads (in `std::vector<std::unique_ptr<Texture2D>>`, matching `BitmapFont`'s
26// established precedent for the same problem) -- callers must keep the converter instance alive
27// for as long as any `Texture2DAtlas` it produced is still in use.
