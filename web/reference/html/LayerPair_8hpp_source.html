5// Ported from MonoGame.Extended's Collisions/LayerPair.cs: an order-independent key identifying an
6// unordered pair of Layer instances (used to record which layer pairs have collision enabled).
7//
8// Upstream orders First/Second using `first.GetHashCode() <= second.GetHashCode()` -- NOT a
9// meaningful value comparison, just upstream's own way of getting an arbitrary-but-consistent
10// order for any two Layer references (Layer never overrides GetHashCode(), so this is C#'s default
11// per-object identity hash, stable for an object's lifetime but not tied to any field). Equals()
12// then compares by ReferenceEquals, not by the ordered fields' values -- so the ordering step exists
13// purely to make (a, b) and (b, a) hash/compare identically, not to express any real ordering
14// relationship between layers.
15//
16// Ported as: order First/Second by raw pointer address instead of a fabricated identity hash --
17// pointer addresses are C++'s own stable, always-available per-object identity, serving exactly
18// the same "arbitrary but consistent" role upstream's identity-hash comparison does, without
19// needing to invent a fake GetHashCode() for Layer (which has no upstream override to preserve).
20// Equals()/GetHashCode() below likewise compare/hash the stored Layer* pointers directly (pointer
21// equality = C#'s ReferenceEquals; std::hash<const Layer*> = a stable per-object hash, matching
22// the *intent* of C#'s identity hash even though the concrete values differ).
23//
24// Upstream's `internal readonly struct` -- kept public, matching the ActorPairKey/
25// CollisionShapeKind2D internal-has-no-C++-equivalent precedent. Constructor takes Layer by const
26// reference (not by pointer) since C++ references cannot be null, dropping upstream's
27// ArgumentNullException.ThrowIfNull checks -- same convention as ActorPairKey.hpp.
