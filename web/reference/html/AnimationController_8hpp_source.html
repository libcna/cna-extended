5// Ported from MonoGame.Extended's Animations/AnimationController.cs. Notable translation
6// decisions:
7// - The constructor takes `IAnimation& definition` (a reference, so upstream's implicit
8// non-null contract is enforced by the type system with no explicit null check needed,
9// matching ActorPairKey's precedent elsewhere in this port) but stores it internally as
10// `IAnimation* definition_` rather than a reference member, so AnimationController itself
11// keeps ordinary (if not copy-assignable in practice, still relocatable-by-pointer) value
12// semantics matching how AnimationComponent stores controllers as non-owning pointers.
13// - `Play()`/`Pause()`/`Unpause()` collapse their C# parameterless-overload-forwards-to-default
14// pattern into a single method with a default argument (see IAnimationController.hpp).
15// - The private `Stop(AnimationEventTrigger)` overload is kept with upstream's exact name
16// (distinguished from the public `Stop()` by arity only, exactly as upstream distinguishes
17// them by C# overload resolution).
18// - `GC.SuppressFinalize(this)` in upstream's public `Dispose()` has no C++ equivalent (no GC)
19// and is dropped; `Dispose(bool disposing)`'s `disposing` parameter is unused by upstream's own
20// base implementation (reserved for subclasses to override), so it is explicitly discarded via
21// `(void)disposing;`, matching GameComponent::Dispose's established idiom for unused override
22// parameters elsewhere in this ecosystem.
23// - TimeSpan has no compound-assignment operators (no operator-=) in sharp-runtime, so
24// `CurrentFrameTimeRemaining -= x` is translated as `currentFrameTimeRemaining_ =
25// currentFrameTimeRemaining_ - x` throughout Update(TimeSpan).
