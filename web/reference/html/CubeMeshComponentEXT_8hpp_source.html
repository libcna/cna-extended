7// 3D counterpart of CNA::Extended::Graphics::Sprite for axis-aligned textured cubes/tiles
8// (the "cube/tile terrain" use case cna-scene::CubeMesh/CubeBatch were designed for --
9// read as reference material, not linked; see this file's own copyright note below).
10// CubeMeshRenderSystemEXT owns one shared unit-cube VertexBuffer/IndexBuffer/BasicEffect
11// (matching TilemapRenderer's/AvatarRenderer's established "one shared effect, texture
12// swapped per draw call" pattern) -- this component only carries per-instance state
13// (texture, world-space size, tint), not its own GPU geometry.
14//
15// cna-scene and cna-extended share the same copyright holder (Robert Vokáč) -- unlike
16// the genuinely third-party MIT code this project's NOTICE.md documents (SlimMath,
17// nickgravelyn's Triangulator, artemis_CSharp), reusing cna-scene's own design here is
18// the project owner's own code informing his own other project, not third-party
19// attribution; no NOTICE.md entry is needed (resolves 3d.md section 9.2's deferred
20// question). This is also a re-implementation, not a copy: cna-scene's CubeMesh/CubeBatch
21// are an immediate-mode batching API with no GPU-buffer-per-instance concept; this file's
22// shape (an ECS component + a system owning one shared unit-cube mesh) is CubeMeshComponentEXT's own design.
