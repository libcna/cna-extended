5// Ported from MonoGame.Extended's Screens/ScreenManager.cs: manages a stack of Screen instances,
6// where the topmost is the active screen while underlying screens can continue updating/drawing
7// in the background based on their own settings.
8//
9// Ownership: Screen* is a NON-owning reference throughout, not std::unique_ptr<Screen>. This is a
10// deliberate choice verified against upstream's own test suite behavior, not assumed: upstream's
11// ScreenManagerTests.cs constructs a Screen, hands it to ShowScreen, later calls CloseScreen(),
12// and THEN asserts on the closed screen's own state (e.g. `Assert.True(screen2.DisposeCalled)`
13// after `manager.CloseScreen()`) -- proving the caller retains and inspects the Screen after the
14// manager is done with it. In C#, this works because GC keeps the object alive as long as the
15// test's own local variable references it; the manager's own "removal" never destroys the object,
16// only calls Dispose() and stops tracking it. A C++ owning std::unique_ptr<Screen> that destroys
17// the Screen on CloseScreen() would leave the caller's own pointer dangling the moment the test
18// inspects it -- so Screen* here is intentionally non-owning, matching the caller-retains-ownership
19// semantics upstream's own tests prove, not upstream's GC mechanism.
20//
21// `Stack<Screen> _screens` + `_screens.Reverse().ToArray()` (bottom-to-top cached array) ->
22// `std::vector<Screen*>` used directly as the stack (push_back/pop_back/back()), since forward
23// iteration over a std::vector already visits bottom-to-top in insertion order -- no separate
24// reverse step needed, a simplification C++'s single all-purpose sequence container affords for
25// free where C# needed a dedicated Stack<T> plus a Reverse().ToArray() cache.
26//
27// ShowScreen(Screen, Transition)/CloseScreen(Transition)/ReplaceScreen(Screen, Transition) take
28// std::unique_ptr<Transitions::Transition> (ownership-transferring), unlike Screen* -- Transition
29// instances are always constructed inline at the call site and never referenced again by the
30// caller afterward (unlike Screen, no test or realistic usage keeps a Transition reference around
31// once handed to a ScreenManager), so ScreenManager taking sole ownership is the correct, safe
32// translation for that specific parameter.
33//
34// Real C#/C++ hazard fixed, not a literal translation: upstream's transition Completed handler
35// disposes and drops the reference synchronously, safe under GC since the object's memory outlives
36// that call. A literal std::unique_ptr::reset() in that same handler would destroy the Transition
37// while its own Update() call is still on the stack above it. See ScreenManager.cpp's header
38// comment for the fix (deferred destruction via transitionCompletedPending_).
