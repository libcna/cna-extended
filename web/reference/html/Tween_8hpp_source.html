5// Ported from MonoGame.Extended's Tweening/Tween.cs. Upstream's `Tween` (non-generic) and
6// `Tween<T> : Tween` (generic) cannot both be named `Tween` in C++ -- unlike C#, C++ does not
7// allow a class template and a non-template class to share one name in the same scope (no arity-
8// based overloading for class names). This file ports only the non-generic base (unchanged from
9// upstream: none of its timing/lifecycle/easing/callback/repeat logic involves reflection). The
10// generic counterpart is renamed TypedTween<TTarget, TMember> -- see TypedTween.hpp for why, and
11// for the pointer-to-member redesign that replaces upstream's TweenMember<T> entirely.
12//
13// `Action<Tween>` callbacks (OnBegin/OnEnd/OnUpdate) -> `std::function<void(Tween&)>`, matching
14// this project's established Func/Action-to-std::function convention. Upstream's `internal
15// Tween(...)` constructor visibility has no C++ equivalent; kept public, matching the
16// `internal`-has-no-C++-equivalent precedent set by ActorPairKey.hpp/CollisionShapeKind2D.hpp
17// elsewhere in this project. `object Target` (untyped) -> `void*`, since the base class has no
18// compile-time knowledge of the concrete target type (only TypedTween<TTarget,TMember> does).
19// Upstream's `string MemberName` abstract property is dropped entirely: it existed only to
20// support Tweener.FindTween(object, string) via reflection-free name comparison, which the
21// pointer-to-member redesign replaces with a type-safe dynamic_cast + direct pointer-to-member
22// comparison in Tweener::FindTween/TweenTo (see Tweener.hpp) -- no name string is ever needed.
