5// *** GENUINE C++ RE-AUTHORING, NOT A LITERAL PORT -- see MatrixChainEffect.hpp for why ***
6// Ported from MonoGame.Extended's Graphics/Effects/DefaultEffect.cs, but the underlying mechanism
7// is entirely re-authored: upstream constructs itself from a precompiled `.mgfxo` bytecode blob
8// (via EffectResource, itself NOT ported -- see NEXT.md for why) containing 4 separate compiled
9// techniques (Position / PositionTexture / PositionColor / PositionColorTexture), switched via
10// `CurrentTechnique = Techniques[shaderIndex]`. CNA's ShaderEffect (this port's base, via
11// MatrixChainEffect) compiles exactly ONE vertex+fragment program per instance -- it has no
12// technique/multi-program concept at all. Ported as a SINGLE GLSL program (see DefaultEffect.cpp
13// for the exact source) that always declares vertex-color and texture-coordinate inputs, toggling
14// their CONTRIBUTION to the final fragment color via two runtime uniform bools (`TextureEnabled`,
15// `VertexColorEnabled`) instead of upstream's compile-time technique selection -- the same visual
16// output (DiffuseColor, optionally multiplied by vertex color and/or a sampled texture) reached by
17// a different, GLSL-idiomatic mechanism. `UpdateCurrentTechnique()`/the 4-technique dispatch is
18// therefore not ported at all; `TextureEnabled`/`VertexColorEnabled` setters just mark the
19// relevant uniforms dirty instead.
20//
21// Vertex attribute layout matches CNA's own confirmed-working SpriteBatch + ShaderEffect
22// integration (examples/easygl_shader_effect_test.cpp in the CNA repo): `vec2 aPos` (location 0,
23// 2D pixel-space position, NOT the 3D VertexPositionColorTexture.Position CNA's DrawUserPrimitives
24// path uses), `vec2 aTexCoord` (location 1), `vec4 aColor` (location 2). This effect is therefore
25// verified compatible with SpriteBatch specifically; upstream's only actual consumer of
26// DefaultEffect (TilemapRenderer/TilemapWorldRenderer, both Phase 7 -- checked via grep before
27// assuming, not guessed) renders 2D tile quads, which is expected to go through SpriteBatch too,
28// but this has not yet been confirmed against the real Phase 7 renderer code (not yet ported).
29// Revisit this assumption when Phase 7 actually wires DefaultEffect into TilemapRenderer.
30//
31// Notable upstream quirk, preserved exactly: upstream's `_diffuseColor` field is never exposed
32// through any public property in DefaultEffect.cs -- only `Alpha` is publicly settable. Since
33// `_diffuseColor` is hardcoded to Color.White and never reassigned, `UpdateMaterialColor()`'s
34// output is always exactly (Alpha, Alpha, Alpha, Alpha) in practice. Not a bug to "fix" by adding
35// a DiffuseColor setter upstream itself doesn't have -- ported as-is, so this class's public API
36// surface has no DiffuseColor accessor either.
