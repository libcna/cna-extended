5// Ported from MonoGame.Extended's Graphics/Texture2DRegion.cs. Notable translation decisions:
6// - Texture2DRegion is a C# reference type that ends up aliased from multiple independent
7// owners at once (a Texture2DAtlas indexes it by both position and name, a Sprite holds it,
8// a NinePatch holds nine of them, GetSubregion hands out fresh ones derived from an existing
9// one) and its mutable `Tag` field means identity (not just value) must be preserved across
10// all of those holders -- so every reference to a Texture2DRegion in this port is a
11// std::shared_ptr<Texture2DRegion>, not a value or a non-owning pointer, matching the
12// project's per-type ownership-reasoning discipline (see ScreenManager.hpp's Screen*/
13// Transition* split for the precedent of reasoning this explicitly rather than defaulting).
14// - `Texture2D Texture { get; }` is a non-owning reference to a GPU resource the region does not
15// own; stored as a raw `Texture2D*` (nullable -- the two test-only constructors below leave it
16// null), matching this project's established non-owning-pointer convention for externally
17// owned graphics resources (e.g. Graphics/Effects/ITextureEffect.hpp).
18// - `ArgumentNullException.ThrowIfNull(texture)` is dropped for the raw-pointer `texture`
19// parameter only where a reference type would make null unrepresentable; here `texture` is a
20// pointer (it can legitimately be null via the test-only constructors' code path), so the
21// check is kept as an explicit `std::invalid_argument` throw on the public texture-taking
22// constructors, matching ActorPairKey.hpp's precedent for pointer parameters.
23// - The `Texture2DRegion(Texture2D texture, string name)` constructor has a genuine upstream bug
24// preserved faithfully: its body ignores the `name` parameter entirely and always delegates
25// with `null`, so the name ends up defaulted from `texture.Name` regardless of what the caller
26// passed. This is exactly what Texture2DRegion.cs does; not a porting mistake.
27// - The two `internal` "used for unit tests only" constructors have no C++ visibility
28// equivalent; kept public and documented as implementation detail, matching
29// CollisionShapeKind2D.hpp/ActorPairKey.hpp's precedent elsewhere in this port.
