5// Ported from MonoGame.Extended's ECS/ComponentMapper.cs. Upstream's non-generic `ComponentMapper`
6// base class stores a C# `Type` (`ComponentType` property); translated as `std::type_index`
7// (`<typeindex>`, wrapping `typeid(T)`) -- a direct, standard C++ mechanism for "map a compile-time
8// type to a runtime-comparable identity," not a reflection substitute needing a design decision
9// (unlike e.g. Tweening's property-path reflection, which had no such direct equivalent).
10//
11// `Components` is a `Bag<T>` of raw component pointers/values -- upstream's `T` is constrained to
12// `class` (a C# reference type), so component instances are heap-allocated reference-type objects
13// whose lifetime is managed by whoever calls `Attach`. This project's `Bag<T*>` (non-owning
14// pointers) mirrors that: `Put`/`Delete` never allocate or free the component itself, matching
15// upstream (`Components[entityId] = component;` / `= null;` never call `new`/dispose either --
16// the caller passed in an already-constructed component and remains responsible for its
17// lifetime).
18//
19// Naming: upstream has both a non-generic `ComponentMapper` class and a generic `ComponentMapper
20// <T>` class in the same namespace -- C# allows two types to share an identifier when their
21// arity differs (arity-based overloading of type names). C++ does not allow a class template and
22// a non-template class to share a name in the same namespace. The generic one is therefore named
23// `ComponentMapperOf<T>` here, a forced rename, not a stylistic choice.
24//
25// Upstream's `Get(Entity entity)`/`TryGet(Entity entity, ...)` convenience overloads (which just
26// forward to the `int entityId` overload via `entity.Id`) are not ported: including `Entity.hpp`
27// here to give `ComponentMapperOf<T>` a definition for them would create a circular include
28// (`Entity.hpp` needs `ComponentManager.hpp`, which needs this file). Nothing internal to this
29// module ever calls the `Entity`-keyed overloads (`Entity` itself always uses its own `Id` with
30// the `int`-keyed overloads directly); confirmed via the upstream test suite too -- only the
31// `int entityId` overloads are exercised anywhere. External callers can call
32// `mapper.Get(entity.getIdProperty())` instead.

105 [[nodiscard]] bool Has(int entityId) const override
106 {
107 if (static_cast<std::size_t>(entityId) >= components_.getCountProperty())
108 {
109 return false;
110 }

112 }
