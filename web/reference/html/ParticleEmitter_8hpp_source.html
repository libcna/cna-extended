5// Ported from MonoGame.Extended's Particles/ParticleEmitter.cs. `Profile` (a C# reference type,
6// always non-null after construction) -> owning `std::unique_ptr<Profiles::Profile>` since
7// `Profile.Point()` etc. return fresh instances upstream doesn't alias elsewhere; getter returns a
8// reference (never null after construction). `TextureRegion` -> `std::shared_ptr<Texture2DRegion>`,
9// matching that type's established shared-ownership convention (nullable, matching upstream's
10// `TextureRegion = null` default). `List<Modifier> Modifiers` -> owning
11// `std::vector<std::unique_ptr<Modifiers::Modifier>>` (nothing else upstream aliases individual
12// Modifier instances); `ModifierExecutionStrategy::ExecuteModifiers` needs a raw-pointer view,
13// built fresh each `Update()` call. `ModifierExecutionStrategy` field -> non-owning pointer into
14// the Serial/Parallel Meyer's singletons (never owned/destroyed by the emitter).
15//
16// `ownedTexture_`/`AdoptOwnedTexture` (added when porting `ParticleEffectSerializer.cs`, no direct
17// upstream field): in C#, a `Texture2D` loaded via `ContentManager.Load<Texture2D>(path)` for this
18// emitter's `TextureRegion` is a GC-managed object kept alive purely by the `Texture2DRegion`
19// referencing it. `ContentManager::Load<T>()` here returns *by value*, and `Texture2DRegion` holds
20// only a non-owning `Texture2D*` (matching its established externally-owned-GPU-resource
21// convention) -- so something has to actually own a texture loaded specifically for this emitter's
22// region. `ParticleEmitter` is that owner, mirroring `Tilemap::ownedTextures_`/
23// `BitmapFont::pageTextures_`'s identical problem and solution -- at most one texture per emitter
24// here (one `TextureRegion` per emitter), so a single `unique_ptr` rather than a vector.
25// `Texture2D.hpp` is included in full here (not just forward-declared, unlike `Texture2DRegion.hpp`'s
26// established non-owning-pointer convention): `AdoptOwnedTexture` is an ordinary (non-template)
27// inline member function whose body move-assigns `unique_ptr<Texture2D>`, and unlike a template,
28// its body is compiled wherever this class definition is parsed -- so every consumer of this header
29// needs `Texture2D` complete right here, not just in `ParticleEmitter.cpp`.
