5// Ported from MonoGame.Extended's FramesPerSecondCounter.cs. Implements CNA's IUpdateable
6// interface, following the same pattern CNA's own GameComponent.hpp/.cpp uses (System::Object
7// base, EnabledChanged/UpdateOrderChanged as public System::EventHandler<System::EventArgs>
8// members, getEnabledChangedEvent()/getUpdateOrderChangedEvent() returning references to them).
9//
10// *** LIKELY UPSTREAM BUG, PRESERVED FOR FIDELITY -- flagged prominently, not silently fixed ***
11// Upstream's `UpdateOrder` property setter raises `EnabledChanged?.Invoke(...)` instead of
12// `UpdateOrderChanged?.Invoke(...)` -- almost certainly a copy-paste error from the `Enabled`
13// setter immediately above it. Reproduced exactly below: setUpdateOrderProperty() raises
14// EnabledChanged, not UpdateOrderChanged. See the regression test in
15// FramesPerSecondCounterTests.cpp that names this discrepancy explicitly. Per this project's
16// "port 1:1, no simplification" requirement, this is not this port's call to fix.
17//
18// `_oneSecondTimeSpan` is `static readonly` upstream (a true constant); ported as a local value
19// constructed where needed rather than a `static const System::TimeSpan` class member, to avoid
20// any static-initialization-order risk (a real bug found and fixed earlier in this project's
21// Matrix3x2::Identity) -- TimeSpan(0, 0, 1) has no observable per-instance-vs-static difference
22// since it never changes, so this is a behavior-preserving simplification of storage duration
23// only, not of logic.
