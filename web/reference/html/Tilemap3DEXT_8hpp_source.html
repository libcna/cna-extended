4// CNA::Extended::World3DEXT::Tilemap3DEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design.
6//
7// 3D/voxel counterpart of CNA::Extended::Tilemaps::Tilemap/TilemapTileLayer, deliberately
8// scoped down per this task's own wording ("decide the exact shape during this phase based
9// on what a real voxel/block world actually needs" -- plan3d.md's Phase 8 entry):
10//
11// - A single sparse (X, Y, Z) -> tile ID grid, not upstream's multi-TilemapTileLayer stack
12// (background/foreground/collision layers etc.) -- a real voxel/block world (Minecraft-
13// style) is a single 3D grid, not a stack of 2D layers; layering isn't the right 3D
14// analog of TilemapTileLayer here. Sparse (std::unordered_map keyed by cell), not a
15// dense 3D array, because real voxel worlds are overwhelmingly empty space (most of a
16// Minecraft-style world above/below ground is air) -- a dense array would waste memory
17// proportional to the full bounding volume regardless of how much is actually built.
18// - Tile ID 0 means "empty" (air), matching the common voxel-engine convention (and this
19// project's own TilemapTileData convention of treating GID 0 as "no tile").
