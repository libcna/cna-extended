5// Ported from MonoGame.Extended's Particles/ParticleEffectSerializer.cs. Upstream's static class
6// with `Deserialize`/`Serialize` methods -> free functions in a matching namespace, per this
7// project's established convention for stateless static-method-only C# classes.
8//
9// `Deserialize` returns `std::unique_ptr<ParticleEffect>`, not `ParticleEffect` by value:
10// `ParticleEffect` has a user-declared destructor and a deleted copy constructor (see
11// `ParticleEffect.hpp`), which suppresses implicit move-constructor generation too -- it is
12// neither copyable nor movable, so a factory function returning a fresh instance must return by
13// pointer. Matches `WorldBuilder::Build()`'s identical precedent from the just-landed ECS/Tilemaps
14// work this session.
15//
16// **Real representational gap, worth reading before touching this file**: upstream's read side is
17// built entirely on `System.Xml.XmlReader`'s streaming-cursor API -- `ReadToDescendant(name)`,
18// `ReadToNextSibling(name)`, and (heavily) `ReadSubtree()` to scope a nested reader to just one
19// element's children. `sharp-runtime`'s `System::Xml::XmlReader` is a much more minimal
20// DOM-cursor-over-tinyxml2 wrapper that has none of those three methods (only `Read()` +
21// node-type/name/attribute access) -- confirmed by reading its header directly, not assumed. The
22// read side of this port is therefore built on `System::Xml::XmlDocument`/`XmlElement`/`XmlNode`
23// (the DOM API) instead, using `SelectSingleNode`/`SelectNodes` (XPath) for the same
24// descend-to-child/iterate-siblings operations upstream's reader methods performed --this is the
25// same DOM-based approach `Content/BitmapFonts/BitmapFontFileReader.cpp` already established for
26// an equivalent "no XmlReader.ReadSubtree available" problem earlier this session. The write side
27// needed no such change: `XmlWriter`'s sequential `WriteStartElement`/`WriteAttributeString`/
28// `WriteEndElement` API has no streaming-vs-DOM gap (writing is inherently sequential), so it
29// ports directly using the already-existing `Serialization::Xml::XmlWriterExtensions` helpers.
