4// CNA::Extended::World3DEXT::ComputeModelBoundsEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design.
6//
7// Added to fix an independently re-verified audit finding (audit.md, A-08):
8// ModelComponentEXT::BoundsEXT defaults to a zero-radius BoundingSphere and is easy for a
9// caller to leave unset, which silently culls a real model every frame (a zero-radius
10// sphere at the origin almost never intersects the view frustum once the model has moved).
11// This gives callers a real alternative to hand-rolling local-space bounds: merge every
12// ModelMesh::getBoundingSphereProperty() via BoundingSphere::CreateMerged, matching this
13// project's "reuse existing CNA/sharp-runtime machinery, don't re-roll it" convention.
14//
15// IMPORTANT, discovered while implementing this fix (not caught by the audit itself):
16// ModelMesh::boundingSphere_ has no public setter and is never written by any code path in
17// `cna` today (verified by grepping `cna`'s entire src/include tree) -- Model's constructor
18// doesn't compute it from part geometry, and there's no content-pipeline loader in scope
19// (see root CLAUDE.md's exclusion list) that would populate it either. So
20// ModelMesh::getBoundingSphereProperty() currently *always* returns a zero-radius sphere at
21// the origin, for every Model constructible today, and this helper's merged result inherits
22// that: it is correct and forward-compatible (the moment `cna` gains any way to populate
23// real per-mesh bounds, this helper immediately starts returning real ones with zero
24// cna-extended changes needed), but it is NOT yet a full fix for A-08's actual concern
25// (silent culling from unset bounds) -- callers still cannot get a non-degenerate bound out
26// of this helper today. A real fix would need to derive bounds from each ModelMeshPart's
27// raw vertex position data instead, which `cna`'s VertexBuffer::GetData only exposes via
28// fixed per-vertex-type overloads (VertexPositionColor, VertexPositionNormalTexture, etc.),
29// not a generic/type-erased read -- doing that generically would mean adding to `cna`
30// itself, which is out of scope without the user's explicit go-ahead (root CLAUDE.md: "Do
31// NOT modify sibling repositories"). Left as an explicit, documented gap rather than
32// silently declared "fixed".
