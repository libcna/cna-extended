5// Ported from MonoGame.Extended's Collisions/SpatialHash.cs: a fixed-cell-size spatial hash
6// implementing ICollisionBroadphase2D. Actors are inserted into every integer cell their
7// BoundingBox2D overlaps; queries collect the union of actors from all cells overlapping the
8// query bounds (de-duplicated, since an actor spanning multiple cells must only be reported once),
9// then re-checked against the exact query bounds since cell membership is an over-approximation.
10//
11// `Dictionary<CellKey, List<ICollisionActor>>` -> `std::unordered_map<SpatialHashCellKey,
12// std::vector<ICollisionActor*>>`. `Dictionary<ICollisionActor, List<CellKey>>` ->
13// `std::unordered_map<ICollisionActor*, std::vector<SpatialHashCellKey>>` (raw-pointer key:
14// std::unordered_map<T*, ...> hashes by address out of the box, no custom specialization needed,
15// unlike SpatialHashCellKey below). `List<ICollisionActor> _actors` ->
16// `std::vector<ICollisionActor*>`, also what GetActors() returns a reference to directly. None of
17// these maps/vectors own the actors (non-owning ICollisionActor* throughout), matching
18// ICollisionBroadphase2D.hpp's established convention.
19//
20// Upstream's `private readonly struct CellKey : IEquatable<CellKey>` is nested inside SpatialHash.
21// Here it is hoisted to a free-standing `SpatialHashCellKey` type at namespace scope instead of
22// staying nested, for a structural reason, not a stylistic one: it is used as an
23// `unordered_map` key INSIDE SpatialHash's own member declarations, so its `std::hash`
24// specialization must be fully visible before those members are declared -- impossible for a type
25// nested in the very class whose body needs that specialization already complete (C++ class bodies
26// cannot be split by an intervening `namespace std { ... }` block and then resumed). Kept public at
27// namespace scope but documented as an implementation detail, matching this project's established
28// `internal`-has-no-C++-equivalent precedent (see CollisionShapeKind2D.hpp/ActorPairKey.hpp) --
29// upstream code outside SpatialHash never references CellKey either.
30//
31// Insert/Remove take ICollisionActor* per the ICollisionBroadphase2D interface signature (not
32// changed here); no null guard is added, matching ICollisionBroadphase2D.hpp's own documented
33// precedent that implementers trust the caller (CollisionWorld2D always passes an already
34// null-checked actor) rather than re-deriving upstream's ArgumentNullException.ThrowIfNull calls.
35// The constructor's ArgumentOutOfRangeException.ThrowIfNegativeOrZero(size.Width)/(size.Height) ->
36// sharp-runtime's System::ArgumentOutOfRangeException::ThrowIfNegativeOrZero(value, paramName),
37// the same static guard-helper API, not re-implemented from scratch.
