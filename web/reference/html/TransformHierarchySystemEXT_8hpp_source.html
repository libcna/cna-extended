4// CNA::Extended::World3DEXT::TransformHierarchySystemEXT -- new, non-upstream addition.
5// See 3d.md/plan3d.md at the repository root for the design.
6//
7// A thin adapter, not a new hierarchy implementation: every frame, for each entity with a
8// Transform3ComponentEXT, resolves ParentEntityIdEXT to the parent entity's own
9// Transform3ComponentEXT (or nullptr if it has none/isn't found) and calls the real
10// Transform3::setParentProperty() -- after that single call, Transform3's own existing
11// dirty-flag machinery (see Transform.hpp) handles all local/world matrix propagation with
12// no further logic needed here. setParentProperty() already no-ops when the parent hasn't
13// actually changed, so calling it unconditionally every frame is cheap.
14//
15// WouldCreateCycle() was added to fix an independently re-verified audit finding
16// (audit.md, A-02): the ECS ParentEntityIdEXT chain -- not yet-resolved Transform3
17// pointers, which this frame hasn't wired yet -- is walked before every setParentProperty()
18// call, so self-parenting and indirect cycles are rejected (falling back to detached)
19// instead of being wired into Transform3's parent-recursive hierarchy, where they could
20// cause unbounded matrix/dirty-propagation recursion.
