4// CNA::Extended::World3DEXT::SkinnedModelComponentEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design.
6//
7// Builds on Microsoft::Xna::Framework::Graphics::SkinnedModelEXT -- a real, already-
8// implemented CNA type (GPU-skinnable mesh + skeleton + animation clips, with a working
9// ComputeBoneTransformsEXT bone sampler), not built here from scratch. SkinnedModelEXT was
10// originally added for cna's Avatar system (AvatarRenderer::EnableRealRenderingEXT), but
11// its bone-hierarchy/keyframe-sampling logic and GPU-backed Parts are entirely avatar-
12// agnostic -- see SkinnedModelEXT.hpp's own header comment ("no attempt is made to align
13// indices, counts, or semantics" with the Xbox Avatar's 71-bone arrays). Reused directly
14// here rather than re-implemented, per plan3d.md's "reuse sharp-runtime/cna types, don't
15// re-roll them" convention (root CLAUDE.md's working rules).
16//
17// Ownership (resolves the question 3d.md section 9.1 deferred to this phase): EffectEXT is
18// a non-owning SkinnedEffect* -- the caller constructs and owns one SkinnedEffect per
19// animated entity (bone transforms differ per entity, so the effect cannot be shared
20// across entities the way a stateless BasicEffect sometimes could be), matching every
21// other component in this ECS being purely non-owning (see ModelComponentEXT.hpp).
22// Modeled directly on AvatarRenderer::DrawRealEXT's real, already-working usage
23// (AvatarRenderer.cpp): a *single* SkinnedEffect is shared across every Part of one
24// SkinnedModelEXT (set once per draw: World/View/Projection/BoneTransforms, then per part:
25// Texture + Apply() + draw) -- unlike ModelComponentEXT, individual ModelMeshPart::Effect*
26// pointers on SkinnedModelEXT::Parts are not used for real rendering at all.
27//
28// BoneTransformsEXT is populated by AnimationSystem3DEXT.Update() each frame (an
29// EntityUpdateSystem) and consumed by RenderSystem3DEXT.Draw() (an EntityDrawSystem,
30// running afterward in the same frame): the transforms are pushed onto EffectEXT
31// immediately before that entity's own draw calls, not eagerly in AnimationSystem3DEXT --
32// see RenderSystem3DEXT.cpp's header comment for why that ordering matters.
