5// Ported from MonoGame.Extended's ECS/EntityManager.cs.
6//
7// Ownership: upstream pools and reuses `Entity` objects (`Pool<Entity>`), relying on the GC to
8// keep every Entity ever created alive for as long as anything (the pool's free list, or the
9// active `_entityBag` slot) references it -- it never explicitly frees one. This project's
10// `Collections::Pool<T>` (already ported) mirrors that recycling behavior exactly but, being a
11// pure C++ pool with no GC backing it, never deletes an obtained/freed item either -- ownership of
12// the actual memory has to live somewhere for the whole EntityManager's lifetime. `allEntities_`
13// below is that somewhere: every `Entity` ever created is heap-allocated once by the pool's
14// factory and owned there for pointer stability; `entityPool_`/`entityBag_` (matching upstream's
15// `_entityPool`/`_entityBag`) hold non-owning `Entity*` into it, exactly mirroring upstream's own
16// "one canonical Entity object per ID, reused via the pool" design -- the only change is *where*
17// the canonical ownership lives (GC root vs. an explicit owning container), not the observable
18// recycling behavior itself.
