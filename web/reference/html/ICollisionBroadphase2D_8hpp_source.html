5// Ported from MonoGame.Extended's Collisions/ICollisionBroadphase2D.cs. Two C# BCL return types
6// have no direct C++ equivalent and are translated for this collision-query hot path rather than
7// wrapped in sharp-runtime's heap-allocating System::Collections::Generic::IEnumerable<T>
8// machinery:
9// - `IEnumerable<ICollisionActor> Query(...)` -> `std::vector<ICollisionActor*>`. Upstream's
10// lazy, `yield return`-based query sequences are ported as eagerly-built vectors -- an
11// implementation-detail difference (laziness) forced by C++ lacking a built-in coroutine-based
12// generator as ergonomic as C#'s `yield return`, not a behavioral one (the set of actors
13// returned is identical either way).
14// - `List<ICollisionActor>.Enumerator GetEnumerator()` -> `const std::vector<ICollisionActor*>&
15// GetActors()`. Upstream's concrete enumerator type strongly implies both broadphase
16// implementations already keep their actors in a `List<ICollisionActor>` internally; exposing
17// that as a direct `const vector&` supports the same "enumerate everything currently stored"
18// use case (CollisionWorld2D's `foreach (ICollisionActor actor in layer.Space)`) without an
19// abstract-iterator-through-a-virtual-interface design that C++ has no lightweight idiom for.
20// ICollisionActor is a reference-type interface in C#; actors are passed/returned as non-owning
21// ICollisionActor* throughout, matching ObjectPool<T>'s IPoolable* convention elsewhere in this
22// port. C++ pointers can be null (unlike this project's usual const-ref-for-non-nullable-parameter
23// convention), but upstream's own ArgumentNullException.ThrowIfNull checks are still dropped here,
24// matching how implementing broadphase types are expected to trust their caller per this project's
25// "trust internal code and framework guarantees" convention -- Insert/Remove are always called
26// from CollisionWorld2D with an already-null-checked actor.
