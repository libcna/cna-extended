4// CNA::Extended::World3DEXT::AnimatedBillboardSystemEXT -- new, non-upstream addition.
5// See 3d.md/plan3d.md and AnimatedBillboardComponentEXT.hpp's own header comment for the
6// design.
7//
8// Each frame, advances every entity's AnimatedBillboardComponentEXT::ControllerEXT
9// (Animations::AnimationController::Update, exactly as AnimatedSprite::Update() does --
10// see AnimatedSprite.cpp) and, if the current frame index changed, re-derives the sibling
11// BillboardComponentEXT's UV rect from the new frame's Texture2DRegion and re-uploads its
12// VertexBufferEXT via SetData -- no new frame-timing engine, this system only keeps a
13// BillboardComponentEXT's texture/UV in sync with an already-advancing AnimationController.
14//
15// Also syncs immediately in OnEntityAdded, not just on a later frame change: without this,
16// a newly-attached entity would show whatever (or no) texture/UV the caller happened to
17// leave on its BillboardComponentEXT until the animation's first frame boundary elapsed --
18// AnimatedSprite::SetAnimation has the same requirement and solves it the same way
19// (assigning the initial TextureRegion immediately, not waiting for the first Update()).
