5// Ported from MonoGame.Extended's Tilemaps/Ogmo/Document/*.cs (~16 files). Grouped into one
6// header for the same reason TiledDocument.hpp groups its own ~24 files: these are pure,
7// behavior-free parse targets, all sharing the `MonoGame.Extended.Tilemaps.Ogmo.Document`
8// namespace.
9//
10// DESIGN DEVIATION, matching TilemapData.hpp/TiledDocument.hpp's own precedent: plain public
11// mutable fields instead of getXProperty()/setXProperty() -- these are C# auto-implemented
12// properties with no logic, semantically indistinguishable from plain fields.
13//
14// Unlike Tiled (XML, reflection-driven XmlSerializer), Ogmo is JSON -- deserialized here via
15// `sharp-runtime`'s `System::Text::Json` (nlohmann `from_json` ADL customization point), matching
16// this project's established convention for JSON-backed types this port owns the definition of
17// (see `Content/TexturePacker/TexturePackerFileContent.hpp`). No reflection gap exists here: C#'s
18// own `System.Text.Json` deserialization for these types is itself driven by source-generated/
19// reflection-based property binding, but the actual *shape* (a tree of named fields) has a direct,
20// non-reflective C++ translation via explicit `from_json` functions, one per type.
21//
22// `Dictionary<string, object> Values` (untyped custom values, see `OgmoLevel`/`OgmoEntity`/
23// `OgmoDecal`) is ported as a raw `nlohmann::ordered_json` object node, not a C++ map -- this is
24// actually a *more direct* translation than upstream's own `System.Text.Json` deserialization
25// target (`Dictionary<string, object>`, where each value becomes a boxed `JsonElement` in
26// practice), since `Converters::ConvertCustomValue` needs exactly the same "inspect the raw JSON
27// value's kind" logic C#'s `JsonElement.ValueKind` switch performs -- nlohmann's `is_string()`/
28// `is_boolean()`/`is_number_integer()`/etc. give that directly, with no intermediate type needed.
29//
30// `OgmoLayerData` (abstract polymorphic base, `[JsonConverter(typeof(OgmoLayerDataConverter))]`
31// upstream) is NOT reflection-based -- `OgmoLayerDataConverter.Read` is a plain field-presence
32// check (does the JSON object have a "tileset"/"data"/"data2D" key? -> OgmoTileLayerData; a
33// "grid"/"grid2D" key? -> OgmoGridLayerData; etc.), translated directly as the free function
34// `ParseOgmoLayerData` below returning `std::unique_ptr<OgmoLayerData>` -- the C++ equivalent of
35// upstream's dispatch, not a `nlohmann::adl_serializer` specialization (which has no natural way
36// to return a polymorphic base pointer), matching this project's precedent of using an explicit
37// factory function for polymorphic JSON dispatch (see `ParticleEffectSerializer.cpp`'s
38// upstream-mirroring manual type-name dispatch, itself confirmed to have no reflection either).
39//
40// `List<Point?> DataCoords` / `List<List<Point?>> DataCoords2D` (`OgmoTileCoordListConverter`/
41// `OgmoTileCoordList2DConverter` upstream: `[[tileX, tileY], [-1], ...]`, a single-element array
42// with a negative value signalling an empty cell) ported as `std::vector<std::optional<Point>>`/
43// `std::vector<std::vector<std::optional<Point>>>`, with the exact same "count >= 2 elements is a
44// valid pair, otherwise empty" parsing rule preserved in `ParseCoordPair` below.
