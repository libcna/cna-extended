5// Ported from MonoGame.Extended's Tilemaps/Rendering/TilemapRendererShared.cs (the
6// `internal static class TilemapRendererShared`; its sibling `LayerModel` class lives in its own
7// LayerModel.hpp, see that file's header comment). `internal` -> ordinary public free functions in
8// this `CNA::Extended::Tilemaps::Rendering` namespace, matching this project's established
9// internal-visibility convention (C++ has no assembly-boundary equivalent).
10//
11// Upstream's only two callers, `TilemapRenderer`/`TilemapWorldRenderer`, are both blocked on a
12// genuine, separately-documented architectural incompatibility between `DefaultEffect`'s GLSL
13// vertex attribute layout and `VertexPositionColorTexture`'s vertex declaration -- see this
14// module's Rendering-phase notes in NEXT.md/plan.md for the full analysis. This file itself has
15// no such dependency (it never touches `Effect`/`DefaultEffect` at all -- only vertex/index buffer
16// construction and pure UV/quad math), so it is ported now regardless: correct, self-contained,
17// independently testable, and ready for `TilemapRenderer`/`TilemapWorldRenderer` to build on
18// directly once that blocker is resolved.
