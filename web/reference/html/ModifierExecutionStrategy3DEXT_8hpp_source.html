7// 3D counterpart of CNA::Extended::Particles::Modifiers::ModifierExecutionStrategy, scoped
8// down deliberately (2026-07-14, per the approved parity plan): only the Serial
9// (single-threaded) strategy exists here, not upstream's Parallel one. 2D's
10// ParallelModifierExecutionStrategy is a documented, deliberately-preserved *upstream* data
11// race (every modifier task shares one ParticleIterator with no synchronization -- see that
12// class's own header comment) kept faithfully as a 1:1 port of a known upstream quirk. Adding
13// an equivalent to genuinely-new (non-upstream) 3D code would mean either reproducing that
14// same real data race on purpose, or independently designing new synchronization upstream
15// never had -- neither is "start with the simplest correct version." Serial-only for now;
16// revisit if a real large-particle-count performance need appears.
17//
18// getSerialProperty() is a function-local static Meyer's singleton (matching
19// ModifierExecutionStrategy.hpp's own established precedent for avoiding static
20// initialization order issues).
