12// CRITICAL fidelity note -- NOT thread-safe or reentrant, by upstream design (not a bug):
13// upstream's `polygonVertices`/`earVertices`/`convexVertices`/`reflexVertices`/`_trianglesBuffer`
14// are `static readonly` fields: shared, reused, mutable buffers across every call to
15// Triangulate/CutHoleInShape. Upstream's own class doc comment explains why: "Per-call
16// allocations have been significantly reduced... It is not something you want to be using each
17// and every frame unless you really don't care about garbage." This is ported below as genuine
18// static class-level mutable member state (not function-local variables, not thread_local) to
19// preserve that exact tradeoff -- do NOT call Triangulate/CutHoleInShape concurrently from
20// multiple threads, or recursively/re-entrantly from within each other; doing so will corrupt
21// the shared buffers, matching upstream's own limitation exactly.
22//
23// Upstream's DEBUG-only Log(...) tracing calls ([Conditional("DEBUG")], and in practice a
24// permanent no-op even in upstream -- its body is a commented-out System.Console.WriteLine) are
25// omitted entirely below rather than ported as dead calls.
26//
27// IsReflex is dead code upstream (never called anywhere in Triangulator.cs, confirmed by
28// grep); ported anyway for completeness as a private static method -- unlike an unused free or
29// anonymous-namespace function, an unused private class method triggers no compiler warning.
