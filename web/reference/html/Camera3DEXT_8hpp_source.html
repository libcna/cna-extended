7// belongs to.
8//
9// Design note, recorded for anyone revisiting this file: an earlier draft of this design
10// (3d.md's original wording) proposed deriving Camera3DEXT from this project's existing
11// Camera<T>/IMovable/IRotatable. Reading those headers before writing this file showed
12// that was wrong: Camera<T>'s interface only uses T for Position/Origin/Center -- half of
13// it (getBoundingRectangleProperty() -> RectangleF, Contains(const Vector2&),
14// Contains(const Rectangle&)) hardcodes 2D types regardless of T, because upstream
15// MonoGame.Extended's Camera<T> was never actually instantiated with anything but
16// Vector2. IMovable/IRotatable are flatly 2D too (Vector2 position, a single float
17// rotation angle, no Quaternion). None of the three actually fit a 3D perspective camera,
18// so Camera3DEXT is a standalone class instead -- see 3d.md section 6.1 for the full
19// finding.
20//
21// Math adapted from cna-scene's own Camera3D (../cna-scene/include/CNA/Scene/Camera3D.hpp,
22// read as reference material only -- cna-extended does not depend on cna-scene, see
23// plan3d.md section 2): Matrix::CreateLookAt for the view matrix,
24// Matrix::CreatePerspectiveFieldOfView for the projection matrix, both real, already-
25// tested CNA math functions -- this file only stores the camera's own parameters and
26// forwards them to that math, it introduces no new matrix math of its own.
