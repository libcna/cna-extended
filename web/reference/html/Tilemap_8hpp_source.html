5// Ported from MonoGame.Extended's Tilemaps/Tilemap.cs. `Properties`/`Tilesets`/`Layers` are
6// owned by value (constructed in the constructor, matching upstream exactly), since
7// `TilemapTilesetCollection`/`TilemapLayerCollection` are themselves the canonical owners of
8// their contents (see those types' own header comments). `internal set` on HexSideLength/
9// StaggerAxis/StaggerIndex is kept as an ordinary public setter, matching this project's
10// established internal-visibility convention (C++ has no assembly-boundary equivalent).
11//
12// `ownedTextures_`/`AddOwnedTexture` (new, no direct upstream field): in C#, each texture
13// `TilemapFactory` loads (`Texture2D.FromStream(...)`) is a GC-managed object kept alive purely
14// by whichever tileset/tile-data/image-layer field references it -- no separate "owner" is
15// needed. In C++, `Texture2D::FromStream` returns *by value*, and `TilemapTileset`/
16// `TilemapTileData`/`TilemapImageLayer` all (correctly, matching this project's established
17// externally-owned-GPU-resource convention) hold only a non-owning `Texture2D*` -- so something
18// has to actually own each loaded texture for as long as the `Tilemap` referencing it is alive.
19// `Tilemap` itself is that owner (mirroring `BitmapFont::pageTextures_`'s identical problem and
20// solution); `TilemapFactory::Build` is the only expected caller of `AddOwnedTexture`, kept
21// public (not a `friend`-restricted API) since free functions can't be granted class-private
22// access, matching this project's established "internal visibility kept public, documented"
23// convention.
