5// Ported from MonoGame.Extended's Tilemaps/TilemapTilesetCollection.cs. Verified via
6// TilemapFactory.cs's real call site (`TilemapTileset tileset = BuildTileset(...);
7// tilemap.Tilesets.Add(tileset);`) that nothing else ever keeps a separate reference to a
8// freshly-built tileset -- this collection (referenced as `Tilemap.Tilesets`) is the sole,
9// canonical owner in practice, just like C# GC keeps a tileset alive purely by virtue of this
10// list referencing it. Translated as an owning `std::vector<std::unique_ptr<TilemapTileset>>`
11// (an earlier draft of this file used a non-owning `TilemapTileset*` vector based on reading
12// this file in isolation -- corrected after reading the actual construction call site, which is
13// exactly the kind of check this project's ownership-decision convention calls for). Includes
14// `TilemapTileset.hpp` in full (not just a forward declaration) since `std::unique_ptr<T>`'s
15// destructor requires `T` to be complete wherever this class's own special member functions are
16// instantiated (matching `TilemapLayerCollection.hpp`'s identical requirement for `TilemapLayer`).
