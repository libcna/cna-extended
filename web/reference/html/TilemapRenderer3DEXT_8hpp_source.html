4// CNA::Extended::World3DEXT::TilemapRenderer3DEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design.
6//
7// 3D counterpart of CNA::Extended::Tilemaps::Rendering::TilemapRenderer: a standalone
8// renderer object with its own Draw(camera, ...) method, matching the real 2D
9// TilemapRenderer's own shape (a renderer instantiated and driven directly by game code,
10// not an ECS system -- unlike every *System3DEXT type elsewhere in World3DEXT, this one
11// deliberately mirrors upstream's actual non-ECS shape, since plan3d.md's own Phase 8
12// bullet names it "TilemapRenderer3DEXT", not "...System3DEXT").
13//
14// Batches visible tiles into CubeMeshRenderSystemEXT::DrawCubeEXT calls (Phase 6's shared
15// cube mesh/effect, extracted for exactly this kind of reuse), frustum-culling each tile
16// individually via Camera3DEXT's BoundingFrustum -- the simplest correct version of the
17// "per-chunk/per-tile culling" plan3d.md calls for; per-chunk batching (merging many tiles'
18// geometry into one draw call, the way TilemapRenderer.cpp's own 2D layer batching does)
19// remains a documented future optimization if profiling ever shows individual per-tile
20// draw calls are a real bottleneck.
