5// Ported from MonoGame.Extended's Tilemaps/LDtk/Document/*.cs (~21 files). Grouped into one
6// header for the same reason TiledDocument.hpp groups its ~24 files: pure, behavior-free JSON
7// parse targets, all sharing the `MonoGame.Extended.Tilemaps.LDtk.Document` namespace.
8//
9// DESIGN DEVIATION, matching TiledDocument.hpp/TilemapData.hpp's own precedent: plain public
10// mutable fields instead of getXProperty()/setXProperty() -- these are C# auto-implemented
11// properties with no logic, semantically indistinguishable from plain fields.
12//
13// Unlike Tiled's XML (deserialized via reflection-driven XmlSerializer, worked around with a
14// hand-written DOM walk), LDtk is plain JSON with every property explicitly
15// `[JsonPropertyName(...)]`-annotated -- this maps directly onto nlohmann's ADL `from_json`
16// customization point (this project's established JSON-DTO-it-owns pattern, see
17// Content/TexturePacker/TexturePackerFileContent.hpp) with no reflection gap at all. Since these
18// are plain-public-field types (not the private-field-plus-friend style TexturePacker uses),
19// `from_json` free functions are declared without `friend` -- there is nothing private to grant
20// access to.
21//
22// `JsonElement?` (LDtkFieldInstance::Value, LDtkTocInstanceData::Fields) has no fixed C++ type --
23// its shape depends on the field's LDtk type (int/float/bool/color/entity-ref/string/array), only
24// interpreted downstream in Converters::Convert. Ported as
25// `std::optional<nlohmann::ordered_json>`, the direct structural analogue: a lazily-typed raw JSON
26// value, exactly matching what `JsonElement` is upstream. `List<object> RealEditorValues` (LDtk
27// editor-only data, confirmed via grep to have zero consumers anywhere in the parser/converter)
28// is ported the same way, as `std::vector<nlohmann::ordered_json>`, for structural completeness
29// rather than dropped.
