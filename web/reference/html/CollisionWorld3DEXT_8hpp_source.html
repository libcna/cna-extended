4// CNA::Extended::World3DEXT::CollisionWorld3DEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design.
6//
7// 3D counterpart of CNA::Extended::Collisions::CollisionWorld2D, brought to parity
8// (2026-07-14, user-requested): named-Layer/LayerPair cross-layer filtering, mirroring
9// CollisionWorld2D.hpp/.cpp method-for-method (Layer3DEXT/LayerPair3DEXT in place of
10// Layer/LayerPair; CNA::Extended::Collisions::UndefinedLayerException reused directly --
11// it's a generic std::string-message type with no 2D-specific logic, so a small
12// World3DEXT -> Collisions include was judged an acceptable trade against duplicating an
13// otherwise-identical file).
14//
15// Two deliberate 3D-specific deviations from the 2D 1:1 mirror, both for backward
16// compatibility with this project's own pre-existing (pre-layer) CollisionWorld3DEXT call
17// sites:
18// 1. QueryCandidates(actor, otherLayerName)/QueryCollisions(actor, otherLayerName)/
19// QueryCollisionPairs(firstLayerName, secondLayerName) default every layer-name
20// parameter to "" (-> the default layer), where CollisionWorld2D leaves them required.
21// This keeps QueryCollisionPairs() -- today's zero-arg call -- compiling unchanged.
22// 2. The no-arg CollisionWorld3DEXT() constructor auto-registers a "default" layer
23// wrapping SpatialHash3DEXT(16.0f) (today's exact default broadphase). This is NOT
24// what CollisionWorld2D() does -- verified directly against CollisionWorld2D.cpp:
25// `CollisionWorld2D() = default;` leaves `layers_` empty, so a bare
26// `CollisionWorld2D world;` followed by `world.Insert(actor)` would itself throw
27// UndefinedLayerException until SetDefaultLayer (or the explicit
28// CollisionWorld2D(unique_ptr<Layer>) constructor) is used. That's a real, if
29// easy-to-miss, 2D API trap this port deliberately does not reproduce: every existing
30// 3D caller already does `CollisionWorld3DEXT()` then `Insert(actor)`/
31// `QueryCandidates(bounds)` with no layer awareness at all, and preserving that
32// zero-setup behavior matters more here than exact-only-in-a-technicality parity with
33// an upstream default-constructor quirk.
