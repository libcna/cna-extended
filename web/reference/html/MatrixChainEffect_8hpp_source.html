5// *** GENUINE C++ RE-AUTHORING, NOT A LITERAL PORT -- user-approved after investigation ***
6// Upstream's MatrixChainEffect is constructed from a compiled XNA/MonoGame Effect bytecode blob
7// (`byte[] byteCode`, ultimately MonoGame's own `.mgfxo` binary format). CNA's own
8// `Effect(GraphicsDevice&, const std::vector<bytecs>&)` constructor -- the literal 1:1 target for
9// this -- ALWAYS throws System::NotImplementedException: CNA has no MojoShader-equivalent bytecode
10// parser/translator yet (tracked as CNA's own future "Phase 74"; see Effect.hpp's doc comment).
11// Investigated and confirmed before proceeding, not assumed. Presented to the user as a design
12// question with three options (skip Effects/* entirely / port only the dependency-free interfaces
13// / manually re-author as a CNA ShaderEffect); the user chose re-authoring.
14//
15// Re-authored on top of CNA's `ShaderEffect` (GLSL-source-based, a NOXNA CNA extension), not raw
16// `Effect`. `Effect`'s Parameters[name] EffectParameter caching model has no ShaderEffect
17// equivalent -- ShaderEffect exposes direct `SetUniformXxx(name, ...)` calls instead, so this port
18// sets the WorldViewProjection uniform directly in OnApply() rather than caching an EffectParameter
19// reference the way upstream's `_matrixParameter` field does; behaviorally identical, just without
20// the caching layer ShaderEffect doesn't provide.
21//
22// Verified against CNA's own working GLSL-ShaderEffect-through-SpriteBatch example
23// (examples/easygl_shader_effect_test.cpp) before choosing a uniform name: that example's shader
24// uses `uniform mat4 projection`, which SpriteBatch itself sets automatically on every compiled
25// program it uses -- to avoid SpriteBatch silently overwriting a name this effect also wants to
26// control (upstream's own World/View/Projection chain, not SpriteBatch's simpler auto-projection),
27// this port's shader instead uses `uniform mat4 WorldViewProjection`, a name SpriteBatch never
28// touches, computed and set here exactly the way upstream's OnApply() does (World * View *
29// (custom-or-default-orthographic) Projection).
30//
31// `Matrix::ToColumnMajor(float[16])` (a NOXNA CNA-provided helper, confirmed via CNA's own
32// EasyGL backend usage at BindDrawParams) converts XNA/FNA's row-major Matrix field layout to the
33// column-major layout GLSL's `mat4` uniforms expect -- verified via CNA's own backend source, not
34// guessed.
