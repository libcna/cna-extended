5// Ported from MonoGame.Extended's Graphics/AnimatedSprite.cs. `IAnimationController Controller
6// { get; private set; }` and the backing `IAnimation _animation` field are both left unset by the
7// single-argument constructor (upstream: `AnimatedSprite(SpriteSheet spriteSheet)` never assigns
8// either -- calling CurrentAnimation, Controller-dependent members, or Update before a subsequent
9// SetAnimation() call throws NullReferenceException upstream). Translated as nullable
10// (std::shared_ptr<SpriteSheetAnimation> / std::unique_ptr<Animations::AnimationController>,
11// both null after that constructor), with an explicit std::logic_error thrown by
12// getCurrentAnimationProperty()/getControllerProperty()/Update() when accessed before
13// SetAnimation() -- preserving the "must call SetAnimation first" contract as a catchable C++
14// exception instead of upstream's implicit null-dereference crash.
15// `ArgumentNullException.ThrowIfNull(spriteSheet)` is dropped: the constructor takes a reference
16// (spriteSheet cannot be null), and upstream's own check is unreachable dead code anyway (the
17// `base(spriteSheet.TextureAtlas[0])` initializer above it already dereferences spriteSheet
18// first, so a genuinely-null spriteSheet would NPE there, never reaching the check).
