4// CNA::Extended::World3DEXT::Particle3DEXT -- new, non-upstream addition. See
5// 3d.md/plan3d.md at the repository root for the design.
6//
7// 3D counterpart of CNA::Extended::Particles::Data::Particle, changing 2D packed-float-array
8// position/velocity/color/scale fields to Vector3, per plan3d.md's Phase 7 scope. A plain
9// value type held in a std::vector<Particle3DEXT> by ParticleEmitter3DEXT, not upstream's
10// #pragma pack(1)/raw-pointer-walked ParticleBuffer -- that tight packing existed to match a
11// C# `[StructLayout(Pack=1)] unsafe struct`'s exact in-memory layout, which has no
12// counterpart here (this is new code, not a byte-compatible port of anything), so a plain
13// std::vector is simpler and equally correct.
14//
15// RotationEXT/MassEXT/TriggeredPositionEXT and ScaleEXT's float->Vector2 change (2026-07-14,
16// user-confirmed) were added to bring the Profiles/Modifiers/Interpolators plugin
17// architecture (Profile3DEXT/Modifier3DEXT/Interpolator3DEXT) to parity with 2D's own
18// Data::Particle fields -- RotationModifier3DEXT/RotationInterpolator3DEXT need RotationEXT,
19// DragModifier3DEXT/mass-weighted gravity need MassEXT, the 3D Container modifiers need
20// TriggeredPositionEXT, and ScaleInterpolator3DEXT needs a non-uniform (Vector2) scale to be
21// meaningful at all -- none of these existed when ParticleEmitter3DEXT only had cone
22// emission + gravity/expiry/color-opacity interpolation baked directly into UpdateEXT.
23// ScaleEXT's new default (Vector2(1,1)) preserves existing uniform-scale visuals unchanged
24// (ParticleRenderSystem3DEXT.cpp's single Vector2(scale,scale) call site now reads
25// particle.ScaleEXT directly instead of constructing that Vector2 itself).
