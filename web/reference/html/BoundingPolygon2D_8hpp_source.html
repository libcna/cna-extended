5// Ported from MonoGame.Extended's BoundingPolygon2D.cs. Contains(...)/Intersects(...)/
6// TryGetCollision(...) now delegate to Collision2D, which is fully ported -- see
7// CollisionResult2D.hpp/Collision2D.hpp. As with the other bounding types, not every shape pair
8// has a TryGetCollision overload upstream: there is no TryGetCollision(BoundingCircle2D) or
9// TryGetCollision(BoundingCapsule2D) here, because upstream itself has none (and Collision2D has
10// no matching TryGetCollisionCircleConvexPolygon/TryGetCollisionCapsuleConvexPolygon function to
11// wrap either) -- confirmed by reading both BoundingPolygon2D.cs and Collision2D.hpp in full.
12//
13// The private ComputeSignedArea helper calls Vector2Extensions.PerpDot upstream (Math/
14// Vector2Extensions.cs, ported later in this phase). PerpDot is a single-line, permanently-fixed
15// formula (a.X*b.Y - a.Y*b.X); it is inlined directly in BoundingPolygon2D.cpp rather than
16// deferring ComputeSignedArea's callers (the constructor's winding-order check and CreateMerged),
17// matching the same "duplicate the trivial, defer the substantial" line drawn for
18// Collision2D::Epsilon elsewhere in this task -- unlike BoundingCapsule2D's LineSegment2D::
19// DistanceToPoint dependency, PerpDot is not a multi-step algorithm.
