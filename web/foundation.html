MATH, SHAPES & COLLECTIONS

Use game-oriented types before reaching for ad hoc helpers.

The foundation headers cover both everyday values and geometry that later modules use for queries, transforms and rendering.

Geometry

RectangleF, CircleF, EllipseF, lines, segments, rays, oriented rectangles and a BoundingRectangle complement the XNA vector/matrix types.

Bounding volumes

BoundingBox2D, circle, capsule, polygon and oriented-box volumes express the shapes that the 2D collision APIs test and query.

Transform and camera helpers

Transform2/Transform3, Camera, OrthographicCamera, matrix/vector extensions and Angle make spatial code more concise.

Triangulation

Polygon and polyline shapes are paired with ear-clipping triangulation helpers, triangles, vertices and cyclic list types for geometry work.

Collections and pools

Bag, Deque, keyed and observable collections, ObjectPool and Pool handle common game-data patterns.

Frame helpers

FPS counters, random extensions, colour helpers, sizing, thickness, intervals and framework extensions cover recurring utility work.

2D COLLISION

Separate broadphase, narrowphase and response.

Collision2D performs precise shape tests; CollisionWorld2D gives those tests an actor model, a broadphase and layer filtering.

1. Represent the actor

Implement ICollisionActor for the game object or an adapter around it. It supplies identity and a collision shape; your own object remains under your ownership.

2. Select a broadphase

Use a QuadTree for spatial subdivision or SpatialHash for bucket-based lookups. Place it inside a Layer.

3. Model collision policy

Register layers in CollisionWorld2D and enable only pairs that should interact — player/world, projectile/enemy, and so on.

4. Query and resolve

Use candidate queries for cheap proximity work, or collision/pair queries for narrowphase results. The result’s translation vector is receiver-relative.

collision query shape
class BoxActor final : public ICollisionActor {
public:
  BoxActor(int id, const BoundingBox2D& box) : id_(id), box_(box) {}
  int getIdProperty() const override { return id_; }
  CollisionShape2D getShapeProperty() const override {
    return CollisionShape2D(box_);
  }
private:
  int id_;
  BoundingBox2D box_;
};

INPUT, TIME & MOTION

Choose polling, events or a state-edge query.

The library deliberately offers both device listeners and current/previous-state wrappers because games often need both forms of input.

InputListeners

KeyboardListener, MouseListener, GamePadListener and TouchListener poll the corresponding cna devices and raise typed events. Settings and event args live beside each listener type.

Extended state wrappers

KeyboardStateExtended and MouseStateExtended retain current and previous snapshots, making “is down”, “was pressed” and “was released” checks deterministic in a conventional update loop.

Timers

GameTimer, CountdownTimer, ContinuousClock and TimerState keep frame time and countdown state independent of rendering.

Tweening

Tweener hosts member-targeted tweens with LinearTween, typed/color variants and a broad EasingFunctions set.

VIEWPORT & DEBUG DRAW

Keep the camera stable across display sizes.

Adapters create a dedicated place for virtual-resolution decisions; vector drawing gives you a rendering path for instrumentation and collision visualisation.

ScalingViewportAdapter

Scale a designed virtual resolution to the actual viewport.

BoxingViewportAdapter

Preserve aspect ratio with letterboxing/pillarboxing when required.

PrimitiveBatch & PrimitiveDrawing

Render lines and debug primitives directly, without turning diagnostics into sprite assets.
