08 · PARTICLES

Compose an effect from emission, motion and appearance.

The 2D particle module follows the Mercury Particle Engine-shaped architecture used by MonoGame.Extended. An effect owns emitters; each emitter spawns particles according to a profile and updates them through modifiers and interpolators.

THE PARTICLE PIPELINE

Each stage has one clear responsibility.

Designing effects becomes much easier when you distinguish where a particle begins from what happens to it after birth.

ParticleEffect

A named, disposable effect containing multiple emitters. It has position, rotation, scale and optional auto-triggering; update it with either GameTime or elapsed seconds.

ParticleEmitter

Owns a particle buffer and configuration for spawning. Trigger the effect or an emitter at a point or along a line segment.

ParticleBuffer and data

Runtime particle storage plus the strongly named float, integer, colour and vector parameter classes that modifiers consume.

Profiles

Profiles describe the initial distribution. They are not “movement”: a circle profile decides how a particle is born, while gravity or velocity modifiers decide how it later moves.

Modifiers

Modifiers run throughout the lifecycle. Their execution strategy controls how a pipeline applies them rather than forcing every effect into one fixed update recipe.

Interpolators

Interpolators map progress through life to colour, hue, opacity, rotation, scale or velocity changes.

BUILDING BLOCKS

Choose the shape and change you actually need.

These types are independent. An effect can contain a simple point emitter with only ageing, or a layered effect with several tuned emitters and interpolation paths.

Profiles

PointProfile, LineProfile, CircleProfile, RingProfile, SprayProfile, BoxProfile, BoxFillProfile and BoxUniformProfile.

Forces and velocity

LinearGravityModifier, DragModifier, VelocityModifier and VortexModifier control motion without custom per-particle code.

Lifetime and containers

AgeModifier, fast opacity fade, circle/rectangle/rectangle-loop containers and rotation modifiers manage expiry and bounds.

Colour and opacity

Colour, hue, opacity and velocity-colour modifiers/interpolators support fire, smoke, magic and impact-style effects.

Shape interpolation

Rotation, scale and velocity interpolators drive motion curves over a particle’s age.

Render order

ParticleRenderingOrder selects the intended draw ordering for active particles.

ASSETS & REUSE

Put tuned effects in source-controlled XML.

Particles are often authored and revisited. Serialization keeps the tuned definition out of imperative gameplay code.

ParticleEffectSerializer

Serializes effect definitions to and from XML. It is the explicit asset-format boundary for 2D effects.

FromFile and FromStream

Convenience factories load an effect definition and use a ContentManager to resolve referenced textures. Stream loading also accepts a base directory for relative resources.

{
  explosionEffect->Update(gameTime);

{

Keep responsibilities separate: gameplay decides when and where to trigger; the particle definition decides distribution and visual evolution. This makes the same effect reusable for multiple events.
