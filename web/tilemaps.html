07 · TILEMAPS

Load the map your level designer already made.

The tilemap module offers one runtime data model, direct readers for Tiled, LDtk and Ogmo, and two independent rendering strategies. There is no MGCB conversion or XNB step in the normal workflow.

ONE DATA MODEL, THREE EDITORS

Pick an authoring tool without changing gameplay-facing map code.

Each parser converts document-specific data into the same Tilemap, layer, tileset, object and property classes.

THE RUNTIME LOAD PATH

Parse, inspect, load renderer, update, draw.

Keep loading and rendering separate: a Tilemap is data; a renderer prepares its graphics-side representation and owns map-animation updates.

  1. 1

    Parse

    Choose the reader for the source format. Pass the graphics device where the parser needs to create referenced runtime textures.

  2. 2

    Inspect data

    Read map dimensions, layers, object layers, named markers, tilesets and typed custom properties from the common model.

  3. 3

    Prepare the renderer

    Call LoadTilemap on the rendering strategy you selected. Re-load deliberately if the data is replaced.

WHAT THE MODEL PRESERVES

Maps are more than a grid of IDs.

Use the data model as a bridge between level-design intent and your gameplay systems rather than baking level decisions into a renderer.

Layers

Tile, group, image and object layers are represented explicitly. Layer collections retain their order and structure.

Objects

Rectangle, ellipse, point, polygon, polyline, tile and text objects allow marker-driven spawning, triggers, collisions and designer annotations.

Tilesets and animation

Tilesets, tile data, per-tile animation frames and flip flags are available independently of the render path.

Properties

Typed tilemap property values carry custom editor data without losing its declared kind.

World maps

TilemapWorld and world renderers serve a collection of maps rather than a single map.

Errors

TilemapParseException and parser interfaces give format loading a defined failure surface.

CHOOSE A RENDERER

SpriteBatch for the common path; geometry when you need it.

Both routes consume the same map model. Choose based on how much control you need over the graphics pipeline, not the editor that produced the map.

TilemapSpriteBatchRenderer

The ordinary 2D route. Draw a map through SpriteBatch and a camera; use TilemapWorldSpriteBatchRenderer for a TilemapWorld.

TilemapRenderer

The direct path builds geometry for VertexBuffer and BasicEffect drawing; use TilemapWorldRenderer for world-level rendering.
