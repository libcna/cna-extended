TEXTURE REGIONS

Give parts of a texture a stable name.

Regions are the common unit shared by sprites, sprite sheets and texture-packer data. They prevent gameplay code from spreading raw rectangle coordinates.

Texture2DAtlas

Owns the named collection of regions belonging to one texture. Create regions manually for a simple sheet or load a direct TexturePacker export through the content module.

Texture2DRegion

Represents a rectangular part of the backing texture. Use it directly when a single sprite or UI piece does not need a full animation model.

Region extensions

Texture2DRegionExtensions supplies convenience operations around the region abstraction so custom draw helpers do not need to unpack its details.

manual atlas setup
Texture2DAtlas atlas("player", &playerTexture);
atlas.CreateRegion(0, 0, 32, 32, "walk0");
atlas.CreateRegion(32, 0, 32, 32, "walk1");
atlas.CreateRegion(64, 0, 32, 32, "walk2");

std::shared_ptr<Texture2DRegion> frame = atlas.GetRegion("walk0");

spriteBatch.Begin();
CNA::Extended::Graphics::Draw(spriteBatch, frame, position, Color::White);
spriteBatch.End();

SPRITES & ANIMATION

Model animation as named frames with explicit timing.

The sprite classes allow a small gameplay object to keep its visual state separate from input, collision and world coordinates.

Sprite

Represents a drawable sprite tied to a region and its transform-facing display data.

SpriteSheet

Collects atlas regions and named animations. A builder defines frame order, duration, looping and ping-pong behaviour.

AnimatedSprite

Uses a sheet animation at runtime. Update it with GameTime, then draw through the graphics extensions.

AnimationController

Controls a sprite animation’s playhead and frame advancement; related interfaces/events expose custom animation work.

Flip flags

FlipFlags captures horizontal/vertical visual mirroring without maintaining a second art asset.

Frame events

AnimationEvent and AnimationEventTrigger let an animation transition become a gameplay hook.

define and update a walk cycle
sheet.DefineAnimation("walk", [](SpriteSheetAnimationBuilder& builder) {
  builder.AddFrame("walk0", TimeSpan::FromSeconds(0.15))
         .AddFrame("walk1", TimeSpan::FromSeconds(0.15))
         .AddFrame("walk2", TimeSpan::FromSeconds(0.15))
         .IsLooping(true)
         .IsPingPong(true);
});

AnimatedSprite player(sheet, "walk");
player.Update(gameTime);

spriteBatch.Begin();
CNA::Extended::Graphics::Draw(spriteBatch, player, playerPosition);
spriteBatch.End();
!

Ping-pong is a looping behaviour: set IsLooping(true) alongside IsPingPong(true). A non-looping animation reaches its final frame and stops, which is the intended one-shot behaviour.

TEXT & UI

Use bitmap fonts and scalable texture panels.

The font module targets AngelCode BMFont files; nine-patch support keeps texture-backed controls sharp at arbitrary UI sizes.

BitmapFont

BitmapFont, characters and extensions load and lay out AngelCode data. Glyph enumeration supports regular string text and StringBuilder text. Multi-page font textures are supported.

NinePatch

Use NinePatch for dialog backgrounds, buttons and panels: corners retain their proportions while edges and centre scale.

SpriteBatch extensions

Graphics extensions offer drawing overloads for the library’s own sprite, region and helper types, so rendering code remains centered on cna’s normal SpriteBatch.

Viewport adapters

Pair text and UI with ScalingViewportAdapter or BoxingViewportAdapter when you need a deliberate virtual resolution.

EFFECTS & INSTRUMENTATION

Extend the render path without assuming MonoGame bytecode.

cna does not load MonoGame .mgfxo effect bytecode. The library therefore implements its helpers on cna’s hand-written ShaderEffect and BasicEffect paths.

Effects

  • DefaultEffect covers the common cna-compatible custom effect case.
  • MatrixChainEffect and IMatrixChainEffect manage an ordered matrix chain for rendering workflows.
  • ITextureEffect identifies effects that consume texture data.

Debug drawing

  • PrimitiveBatch batches direct primitive work.
  • PrimitiveDrawing provides convenience shape and line operations.
  • Draw collision shapes, navigation diagnostics or editor guides from the exact data that gameplay uses.
↗

Rendering order: in a typical 2D frame, begin a SpriteBatch for map/sprites/UI work, keep direct primitive/debug work in the appropriate batch or graphics pass, and avoid nesting redundant SpriteBatch begin/end pairs around APIs that already control their own draw sequence.
