02 · GETTING STARTED

Get a real cna backend behind your game.

cna-extended is a static CMake library. You normally build it next to cna and sharp-runtime, then link the public CNA::Extended alias from your own executable.

Build with cna ↓Understand the architecture
terminal
# From the cna-extended checkout
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Debug \
  -DCNA_EXTENDED_LINK_CNA=ON
cmake --build build -j$(nproc)
ctest --test-dir build
linked configuration: graphics, examples and runtime tests

DEPENDENCY LAYOUT

Keep the sibling checkout model, or override the paths.

The project intentionally follows the dependency pattern used by the surrounding ecosystem. It does not fetch a moving dependency tree during configuration.

Default on-disk layout

cna-extended/this library
↔
cna/XNA/FNA C++23 runtime and graphics backends
↔
sharp-runtime/required .NET BCL surface

Default discovery

../cna and ../sharp-runtime are inspected as sibling directories. An already-defined parent CNA target wins, which makes embedding in a larger CMake build straightforward.

Custom checkout locations

Set CNA_EXTENDED_CNA_DIR and CNA_EXTENDED_SHARP_RUNTIME_DIR when your source tree uses a different layout. The paths must expose the normal include and CMake project structure.

THE NORMAL BUILD

Use the linked mode for an executable game.

Anything that touches GraphicsDevice, SpriteBatch, textures, rendering-backed tilemaps or the graphics examples needs a real cna build.

  1. 1

    Choose a cna backend

    EASY_GL is the default. SDL_RENDERER, BGFX and VULKAN are selectable with CNA_EXTENDED_CNA_BACKEND.

  2. 2

    Enable the backend link

    Pass -DCNA_EXTENDED_LINK_CNA=ON. CMake adds the sibling cna project only if a parent target does not already exist.

  3. 3

    Build and test

    Build the static library and optional examples/tests, then run ctest --test-dir build.

configure a backend
cmake -S . -B build-easygl \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCNA_EXTENDED_LINK_CNA=ON \
  -DCNA_EXTENDED_CNA_BACKEND=EASY_GL
cmake --build build-easygl -j$(nproc)
your CMakeLists.txt
add_subdirectory(path/to/cna-extended)

add_executable(my_game main.cpp)
target_link_libraries(my_game PRIVATE CNA::Extended)
target_compile_features(my_game PRIVATE cxx_std_23)
i

Warning policy: cna-extended itself builds with -Wall -Wextra -Werror, or /W4 /WX on MSVC. Treat a clean library build as the baseline before debugging runtime behaviour.

FAST API CHECKS

Headers-only mode is useful, but intentionally limited.

The default standalone configuration does not build cna. It lets you compile-check the library surface when a full graphics backend is not needed.

Use it for

  • Verifying include paths and C++23 compatibility.
  • Working on pure helper code or templates.
  • Fast integration checks in an environment without graphics dependencies.

Do not mistake it for

  • A runnable graphics configuration.
  • A way to execute rendering-backed tests.
  • A substitute for validating Texture2D, SpriteBatch or GraphicsDevice code.
headers-only compile check
cmake -S . -B build-headers \
  -DCMAKE_BUILD_TYPE=Debug \
  -DCNA_EXTENDED_LINK_CNA=OFF
cmake --build build-headers -j$(nproc)

FIRST USE

Start with a small update-only feature.

Tweening is a good first module because it requires no graphics device and shows the library’s pointer-to-member style.

main.cpp
#include <CNA/Extended/Tweening/EasingFunctions.hpp>
#include <CNA/Extended/Tweening/Tweener.hpp>
#include <Microsoft/Xna/Framework/Vector2.hpp>

using CNA::Extended::Tweening::EasingFunctions;
using CNA::Extended::Tweening::Tweener;
using Microsoft::Xna::Framework::Vector2;

struct Player { Vector2 Position{0.0f, 0.0f}; };

Player player;
Tweener tweener;
tweener.TweenTo(&player, &Player::Position, Vector2(100.0f, 0.0f), 0.5f)
       ->Easing(EasingFunctions::QuadraticOut);

// Once per frame, normally from your game's Update().
tweener.Update(1.0f / 60.0f);
