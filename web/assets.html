CONTENT HELPERS

Resolve referenced files consistently.

Files such as an atlas export or font definition may refer to sibling textures. The content helpers keep resolution policy explicit instead of scattering filesystem code across every loader.

ContentManager extensions

ContentManagerExtensions complements cna content management for the direct-format workflow.

ExternalResourceResolver

The resolver abstraction represents how a referenced external resource is found and opened.

ExternalResourceResolvers

Provides concrete resolver selection/helpers so format readers have a shared path-resolution mechanism.

Keep relative assets together: store a source file and the images it references in a predictable directory. It makes local loading, packaging and future editor workflows all easier to reason about.

JSON & XML UTILITY LAYERS

Serialize cna-friendly values without rewriting converters.

The serialization modules are helpers for the runtime data formats. They are not a new generic content pipeline.

JSON

JsonContentLoader and TextContentLoader support runtime document loading. Converters cover colour, vectors, rectangle/size forms, intervals, thickness, texture atlases/regions, content managers and related cna values.

XML

XmlNodeExtensions, XmlReaderExtensions and XmlWriterExtensions provide typed parsing and writing helpers for XML-backed data such as particle effects.

i

Validation belongs at the format boundary: parse errors and malformed typed fields should fail when the file is read, not become silent default gameplay values later. The parser and conversion APIs are the right place to surface these errors.

INTENTIONALLY EXCLUDED PIPELINE

Why the documentation does not tell you to produce XNB files.

The original MonoGame.Extended includes design-time pieces that exist only to consume MGCB pipeline output. They have no useful direct runtime counterpart in this C++ library.

Not part of cna-extended

  • MonoGame.Extended.Content.Pipeline and its processor/importer toolchain.
  • XNB-side ContentTypeReader classes whose sole purpose is consuming pipeline output.
  • An invented replacement packaging format that duplicates the same complexity.

The direct-format alternative

  • Use Tiled/LDtk/Ogmo files directly for level data.
  • Use TexturePacker JSON and AngelCode BMFont files for 2D presentation.
  • Use XML for particle definitions and the 3D JSON schema for voxel grids.
